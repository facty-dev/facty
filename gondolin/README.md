# gondolin — the Facty VM image config (vendored)

A copy of the [gondolin-pi](https://github.com/earendil-works/pi-coding-agent)
image config, vendored in this repo so anyone who clones Facty can build and
run the sandboxed agent VMs without the global `~/code/gondolin-pi` workspace.
The Facty tooling (`scripts/agent-pi.sh`, `scripts/vm-session.sh`, the
`Makefile`) passes THIS copy in by default.

## Contents

| Path | What |
|---|---|
| `gondolin-pi.sh` | the runner — resumes the snapshot, mounts the project at `/workspace`, sets the egress allow-list, execs pi |
| `build-snapshot.sh` | the image build — boots a fresh gondolin VM, installs pi + textual + git + the pi extensions + the skills, then snapshots it |
| `skills/` | the **facty-optimized** skill set baked into the image (33 skills: the SDLC agents' planning / coding / review / docs skills, plus two pi-marketplace skills — `bdd` (Gherkin feature files, MIT) and `adr-skill` (ADRs)). Trimmed from the host's 89-skill general library to what Facty's agents need; `SKILL-INDEX.md` is regenerated by `scripts/generate-skill-index.py` |
| `snapshots/` | the built image (`pi-sandbox.qcow2`) — a build artifact, **gitignored** |

The image carries `textual` (pip, system python3) and `git`, so the `facty`
CLI and the Textual workbench also run inside the VM with zero runtime
installs — the runtime egress allow-list has no pypi, by design.

**No web search, by design.** There is no web-search skill or CLI in the
image, and no web hosts in the runtime egress allow-list
(`api.mistral.ai` + `registry.npmjs.org` only): Facty cases handle
sensitive data, so the VM must not be able to leak it to an untrusted
third party. Web research happens on the host, or not at all for
sensitive cases.

## Usage (from this repo)

```bash
make vm-image        # build the snapshot (one-time per machine; ~5-10 min)
make vm-up           # boot the long-lived SDLC session (from YOUR terminal)
make vm-status       # session state (sandbox-safe)
make agent-decision PHASE=discovery TASK="..."   # run a decision agent
make agent-coding TASK=<task-file>               # run a coding agent
make vm-down         # stop the session
```

Or directly:

```bash
./gondolin/gondolin-pi.sh build --force    # rebuild the snapshot
./gondolin/gondolin-pi.sh <project-dir>    # interactive pi session
```

## Env

- `GONDOLIN_PI` — runner path (default: this repo's `gondolin/gondolin-pi.sh`)
- `PI_SNAPSHOT` — snapshot path (default: this repo's `gondolin/snapshots/pi-sandbox.qcow2`)
- `PI_MODEL` / `PI_THINKING` — agent model overrides (default `mistral-large-4` / `max`)
- `MISTRAL_API_KEY` — required; passed as a gondolin **host-secret** (the guest
  only ever sees a placeholder; the host proxy substitutes the real value into
  outbound requests to `api.mistral.ai`)

## Requirements

- `gondolin` (the micro-VM CLI — `brew install gondolin` or per its docs)
- `MISTRAL_API_KEY` in the environment
- build-time egress to `dl-cdn.alpinelinux.org`, `pypi.org`,
  `files.pythonhosted.org`, `registry.npmjs.org`, `github.com` (the build
  installs packages; runtime egress is the explicit allow-list only)

## Provenance

Vendored from the host's global `~/code/gondolin-pi` workspace. To reuse this
config for other projects, copy this directory back out to
`~/code/gondolin-pi` (or point their tooling at it via `GONDOLIN_PI`).
